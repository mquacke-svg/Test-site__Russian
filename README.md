# Жак-Андрэ — Next.js-версия интернет-магазина

> Архивная реализация. С 31.10.2026 сайт онлайн использует PHP; актуальные исходники находятся в [ветке codex/bakery-php](https://github.com/mquacke-svg/Test-site__Russian/tree/codex/bakery-php). Эта ветка сохраняет Next.js-версию для разработки и истории.

Сайт пекарни в шалфейно-зелёной, сливочной и персиковой палитре: каталог, корзина,
самовывоз/доставка, гостевые заказы, VK/Google, кабинет и административная панель.
Это тестовая версия: реальные заказы в пекарню не передаются, онлайн-оплаты нет.

## Быстрый запуск (PowerShell, Node.js 24)

```powershell
npm ci
npm run setup
npm run dev
```

Откройте **http://localhost:3000**. Используйте именно `localhost`, как указано
в `BETTER_AUTH_URL`, чтобы адрес совпадал с OAuth-настройками и проверкой Origin.
Команда `dev` запускает Next.js и обработчик уведомлений Telegram. Остановка — Ctrl+C.

`setup` создаёт локальный секрет в `.env.local`, применяет миграции и загружает
исходные товары/адреса. Повторный запуск не перезаписывает товары, цены, варианты
и настройки, изменённые администратором. Данные находятся в `.local/bakery.sqlite`,
загруженные фотографии — `.local/uploads`. Пути можно задать через `DATABASE_PATH`
и `UPLOADS_PATH`. Эти каталоги и секреты исключены из Git.

При размещении с каталогами версий указывайте абсолютные пути к общей БД и фото
вне каталога релиза. Один и тот же `UPLOADS_PATH` должен использоваться сайтом,
резервным копированием и восстановлением. Существующие фото переносите при
остановленном сайте, сохраняя имена файлов и исходную копию до проверки.

Production-проверка:

```powershell
npm run build
npm start
```

Не запускайте `dev` и `start` одновременно на одном порту. После изменения
переменных окружения перезапустите сервер и обработчик уведомлений.

## Администратор

```powershell
npm run admin:create
```

Введите собственные email и пароль (минимум 12 символов). Пароль скрыт при вводе
в интерактивном терминале. В базе хранится хеш. Общего пароля и автоматического
создания администратора нет. Вход: **http://localhost:3000/login?admin=1**.

Для автоматизации команда также читает `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD`
из окружения текущего процесса. Не сохраняйте пароль в Git и не передавайте его
в аргументах команд. Команда не меняет уже существующие аккаунты.

В `/admin` доступны заказы и смена статусов, создание/редактирование товаров,
варианты объёма, загрузка фото, доступность и настройки доставки. Для фото принимаются
JPEG/PNG/WebP до 5 МБ; сервер декодирует и перекодирует изображение в WebP.

В карточке товара администратор может указать целое количество в наличии; пустое
поле означает, что остаток неизвестен и численный учёт для товара выключен. Для
напитка остаток общий для всех объёмов. Корзина не резервирует товар: при заказе
остаток проверяется и уменьшается в транзакции, при отмене возвращается. Если
учёт отключён до отмены, возврат количества не выполняется. Фактические остатки
нужно внести вручную и поддерживать в актуальном состоянии.

## Регистрация и вход

Покупатель регистрируется по логину и паролю, без почты и подтверждающего кода.
Логин — от 3 до 30 латинских букв, цифр, точек или знаков подчёркивания;
регистр букв при входе не учитывается. Пароль — от 8 символов. После регистрации
сразу открывается личный кабинет. Уже существующие аккаунты могут входить по email.
SMTP для регистрации не нужен.

Пользователи, хеши паролей и сессии хранятся в SQLite. Для совместимости с Better
Auth новые аккаунты получают внутренний адрес из hex-кодировки логина в домене
`username.bakery.invalid`. Это не почтовый ящик; старые адреса и способы входа
сохраняются. `npm run setup` применяет миграции без перезаписи аккаунтов.

## VK ID и Google

Провайдеры подключены через Better Auth, но **нужны приложения владельца**.
До добавления ключей кнопки этих провайдеров скрыты. Заказ без регистрации работает.

### Google

1. В Google Cloud Console создайте проект, настройте экран согласия OAuth.
2. Создайте OAuth Client типа Web application.
3. Добавьте разрешённый адрес возврата:
   `http://localhost:3000/api/auth/callback/google`.
4. Для приложения в тестовом режиме добавьте свои тестовые Google-аккаунты.
5. Запишите `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` в `.env.local`.

Документация: https://better-auth.com/docs/authentication/google

### VK ID

1. В кабинете VK ID создайте веб-приложение.
2. Укажите адрес сайта `http://localhost:3000` и redirect URI
   `http://localhost:3000/api/auth/callback/vk`.
3. Включите необходимые разрешения профиля/email. Встроенному провайдеру нужен email;
   если VK не возвращает его, вход не завершается, а сайт предлагает повторить
   попытку или оформить заказ гостем.
4. Запишите `VK_CLIENT_ID` и `VK_CLIENT_SECRET` в `.env.local`.

Документация: https://better-auth.com/docs/authentication/vk

Секреты не отправляйте в чат. После настройки перезапустите приложение и проверьте
оба реальных входа, отмену авторизации и повторный вход. Автоматическое объединение
аккаунтов по email отключено. Гостевые заказы можно добавить в кабинет кнопкой
«Сохранить гостевые заказы»: нужны текущие guest-cookie и авторизованная сессия.

## Telegram

1. Создайте бота через официальный `@BotFather` в Telegram.
2. Добавьте бота в отдельный тестовый рабочий чат и разрешите отправку сообщений.
3. Получите ID этого чата через Telegram Bot API (обновления `getUpdates` после
   сообщения боту/в чате) или из собственных инструментов администрирования.
4. Добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env.local`.
5. Перезапустите `npm run dev` и оформите тестовый заказ.

Уведомления содержат номер, товары, сумму и способ получения. Телефона и адреса в
сообщении нет. Ошибка отправки не отменяет заказ: очередь хранится в SQLite,
обработчик повторяет попытки с увеличивающейся задержкой (до часа). После добавления
ключей будут отправлены и ранее накопленные тестовые уведомления. При сетевом
тайм-ауте после приёма сообщения Telegram повтор может дать дубликат сообщения;
номер заказа остаётся тем же, сам заказ не дублируется.

Документация: https://core.telegram.org/bots/api#sendmessage

## Правила магазина

- Деньги хранятся в копейках. Сервер не доверяет ценам из браузера.
- Доставка: Краснодар, 250 ₽; бесплатно от 2 000 ₽ товаров; минимум 500 ₽ товаров.
  Самовывоз бесплатный, без минимальной суммы. Значения меняются в админке.
- Время и адрес подтверждает сотрудник. Геокодирование и онлайн-карта курьера не подключены.
- Остаток может быть известным числом либо не учитываться; «В продаже» управляет доступностью.
- У товара без цены кнопка покупки отключена; объёмы напитка — разные позиции корзины.
- Названия, варианты и суммы фиксируются в заказе и не меняются после редактирования каталога.
- Ключ оформления защищает от дублей. После потерянного ответа повторное открытие
  checkout в той же вкладке проверяет сохранённую попытку заказа.
- Корзина гостя живёт 30 дней; после входа объединяется с аккаунтом однократно.
- Гостевой заказ доступен только владельцу соответствующей cookie, аккаунту,
  которому он явно перенесён, или администратору. Одного номера/URL недостаточно.
- Cookies необходимы для корзины, входа и закрытия уведомления. Аналитики нет.
- Начальные цены — снимок от 22.12.2025, не подтверждённый актуальный прайс.

## Тесты

```powershell
npm run typecheck
npm test
npm run build
npm audit
```

Vitest создаёт отдельную временную базу и удаляет её после проверки. Он проверяет
границы доставки, варианты, недоступные товары, изменение цен/параметров заказа,
изоляцию заказов, повторное оформление, объединение корзин и реальные локальные
сессии Better Auth. Социальные провайдеры требуют отдельной проверки с аккаунтами.

Для всех браузерных сценариев, включая HTTP-проверки сессии и админки, используйте
изолированный запуск (нужен установленный Microsoft Edge):

```powershell
npm run build
npm run test:e2e:isolated
```

Команда создаёт временную БД с seed-каталогом, запускает отдельный сайт на свободном
порту без внешних интеграций и удаляет тестовые данные после завершения. Рабочая БД
и запущенный локальный сервер не используются. Для существующего тестового сайта:

```powershell
npm run test:e2e
```

Браузерные тесты создают явно тестовый заказ
в текущей базе; используйте тестовый Telegram-чат либо оставьте Telegram отключённым.
Адрес можно изменить переменной `E2E_BASE_URL`. Скриншоты четырёх ширин сохраняются
в `test-results/`, отчёт — в `playwright-report/`. Тест отключённых провайдеров
рассчитан на окружение без OAuth-ключей. Проверки с прямым доступом к тестовой БД
выполняются только изолированным запуском.

## Резервная копия и восстановление

```powershell
npm run backup
```

Создаёт согласованный снимок SQLite и копию загруженных изображений в
`.local/backups/<timestamp>`. `.env.local` храните отдельно: секреты в архив не входят.
На время копирования фото избегайте одновременных загрузок из админки.

Для восстановления **сначала остановите все процессы сайта/обработчика**, затем:

```powershell
npm run restore -- 2026-10-25T20-45-19-465Z --server-stopped
```

Замените пример на имя вашей папки, включая `before-restore-*` для отката предыдущего
восстановления. Проверяется целостность базы; БД и фото сначала подготавливаются
во временных каталогах, прежнее состояние сохраняется в `before-restore-*`.
При ошибке замены выполняется откат. Аварийное завершение процесса или отключение
питания между заменой БД и фото требует проверки и восстановления из страховочной
копии. После успешного восстановления запустите сайт.

## Архитектура и материалы

- `lib/schema.ts`, `drizzle/` — схема и миграции; `lib/shop.ts` — бизнес-операции.
- `app/api/shop/[...path]/route.ts` — каталог, корзина, расчёт, заказы и админка.
- `lib/auth.ts`, `/api/auth/*` — Better Auth и OAuth. Все мутации магазина проверяют Origin,
  админские операции — серверную роль, оформление — ограничения частоты запросов.
- `data/` — только исходные данные для первого заполнения; работающий сайт читает базу.
- `public/images/ASSET_SOURCES.md` — происхождение hero и точный prompt генерации.
- `public/fonts/` — локальные Playfair Display/Inter с кириллицей и лицензиями OFL.

Перед реальным запуском нужны проверенные цены, реальные OAuth/Telegram-подключения,
домен и HTTPS, реквизиты владельца и утверждённые документы, правила доставки,
резервное копирование и мониторинг. Локальная версия специально помечена тестовой
и закрыта от индексации.
