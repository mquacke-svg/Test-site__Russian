# «Жак-Андрэ» — простой PHP-магазин

HTML/CSS, обычный JavaScript, PHP 8.3 и SQLite. PHP формирует страницы и обрабатывает формы; Node.js, npm и сборка для работы сайта не нужны. Сохранены каталог, корзина, заказы, кабинет и админка. VK, Google, Telegram и онлайн-оплата не используются.

Опубликовано: https://case-garage.fun. Памятка для защиты — `docs/DEFENSE.md`; размещение и откат — `docs/DEPLOYMENT.md`.

## Данные после клонирования

Рабочая база, аккаунты, сессии, загрузки и закрытая конфигурация не публикуются. Для запуска магазина требуется существующая совместимая база, перенесённая владельцем отдельно в `.local/bakery.sqlite` либо указанная через `DATABASE_PATH`. `setup.php` не создаёт исходный каталог. Браузерные тесты также требуют такой локальной базы и работают только с её изолированной копией. Серверные тесты создают собственные тестовые данные.

Предыдущая реализация и её исходный каталог сохранены в [ветке codex/bakery-site](https://github.com/mquacke-svg/Test-site__Russian/tree/codex/bakery-site). Повторная проверка 31.10.2026 описана в `BROWSER_QA.md`.

## Локальный запуск Windows

Из каталога проекта:

```powershell
$php = "$env:USERPROFILE\.codex\tools\php83\php.exe"
& $php scripts/check-env.php
& $php scripts/setup.php
.\scripts\start.ps1
```

Открыть **http://127.0.0.1:3083**. Остановка — Ctrl+C. Другой PHP: `scripts/start.ps1 -Php C:\php\php.exe`; другой порт: `-Port 3084`. Встроенный PHP-сервер предназначен для локальной проверки.

`setup.php` проверяет уже перенесённую базу и добавляет служебную таблицу ограничения запросов; товары и аккаунты не перезаписывает. Пустой каталог автоматически не создаётся. Админка — `/login?admin=1`, вход существующим аккаунтом сотрудника.

## Устройство

- `public/` — единственный открытый веб-каталог: контроллер, стили, JavaScript, изображения и шрифты.
- `views/` — HTML-шаблоны с небольшими PHP-вставками.
- `lib/` — запросы PDO, правила магазина, вход, сессии и проверка прав.
- `.local/` — закрытые данные: SQLite, загруженные фотографии, файлы сессий, настройки и резервные копии.
- `tests/` — изолированные проверки, не использующие рабочую БД.

Настройки задаются переменными окружения либо массивом в `.local/config.php`: `APP_URL`, `DATABASE_PATH`, `UPLOADS_PATH`, `SESSION_PATH`, `BACKUP_PATH`. Окружение имеет приоритет. На сервере использовать абсолютные пути к общим данным вне каталога релиза. `APP_URL` должен точно совпадать с адресом браузера, включая протокол и порт.

PHP нужны расширения `pdo_sqlite`, `sqlite3`, `intl`, `scrypt` 2.0.1, `gd` с WebP, `mbstring`, `fileinfo` и `session`. Проверка — `php scripts/check-env.php`. Локальная установка находится в профиле пользователя; системный PATH не изменялся.

## Вход и данные

Логин: 3–30 латинских букв, цифр, точек и подчёркиваний; регистр не учитывается. Пароль обязателен, максимум — 128 символов. Старые аккаунты могут входить по email. Хеши scrypt совместимы с прежним Better Auth, поэтому прежние пароли сохраняются, а новые аккаунты остаются совместимыми с откатом. Пароли не хранятся открытым текстом; `intl` сохраняет прежнюю Unicode-нормализацию.

Вход хранится в серверной сессии до 7 дней бездействия. `bakery_session` содержит только идентификатор; `bakery_guest` сохраняет связь с гостевой корзиной до 30 дней, `bakery_cookie_notice` — закрытие уведомления до года. На HTTPS служебные cookies используют Secure; сессия и гостевой токен также HttpOnly. Все изменения проверяют CSRF, административные действия — роль из базы.

Цены хранятся целыми копейками. Итог, наличие и уменьшение остатков проверяются сервером в транзакции; повторная отправка одной попытки не создаёт второй заказ. Пользователь видит доступность товара, точные остатки — только сотрудник.

## Проверка

```powershell
& $php tests/auth-test.php
& $php tests/shop-test.php
& $php tests/backup-test.php
```

Браузерные проверки — отдельный необязательный инструмент разработки. Для них нужны Node.js 20+ и установленный Microsoft Edge; PHP-сайту эти зависимости не нужны:

```powershell
npm ci --ignore-scripts
$env:PHP_BINARY = $php
npm run test:e2e
```

Скрипт создаёт изолированную копию `.local/e2e.sqlite`, очищает в ней аккаунты и заказы, использует случайные тестовые пароли и отдельные каталоги сессий/загрузок. Тестовый PHP-сервер на порту 3084 запускается и останавливается автоматически. Рабочая база не изменяется. Скриншоты и журнал — `.local/e2e-results/`. Дополнительные браузеры не скачиваются; `node_modules/` и тестовые данные не нужно загружать на хостинг.

Дополнительно проверить `/` и `/menu` на телефоне и компьютере, клавиатуру, формы, изображения, корзину, вход и оформление заказа. Пройденные программные тесты сами по себе не подтверждают визуальное совпадение.

## Резервная копия и восстановление

Остановить сайт перед обеими командами, чтобы SQLite и фотографии относились к одному моменту:

```powershell
& $php scripts/backup.php --server-stopped
& $php scripts/restore.php 20261031-120000-a1b2c3d4 --server-stopped
```

Во второй команде заменить пример на имя созданной копии. Флаг подтверждает остановку: команда не останавливает веб-сервер самостоятельно. Копия содержит только SQLite, uploads и manifest с SHA-256; настройки и секреты не включаются. По умолчанию копии лежат в `.local/backups`.

Восстановление проверяет состав, контрольные суммы и целостность SQLite до замены данных. Прежние SQLite, WAL/SHM и uploads сохраняются рядом под именами `*.before-restore-*`; пути выводятся командой и записываются в отчёт. При ошибке переименования отменяются. Незавершённые `.partial`/`.restore-*` не считаются готовыми копиями.

Откат версии приложения выполняется с **актуальной базой и uploads**. Восстановление старой резервной копии отменяет более поздние изменения, поэтому его нельзя использовать как обычный откат кода после новых заказов.
